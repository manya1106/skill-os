# SkillOS E2E Tests - Complete Guide\n\n## Overview\n\nThis directory contains comprehensive end-to-end tests for SkillOS using Playwright. The tests are organized into three main components:\n\n### Components\n\n#### 1. **page-objects.js** - Page Object Model\nDefines reusable page objects that encapsulate UI elements and their interactions:\n\n- `BasePage` - Base class with common functionality\n- `LoginPage` - Login/authentication flows\n- `RegisterPage` - User registration\n- `DashboardPage` - Main dashboard with stats (XP, Streak, Goals)\n- `GoalWizardPage` - Learning goal creation\n- `ResourcePage` - Adding learning resources\n- `AnalyticsPage` - Analytics and insights\n- `RecommendationsPage` - Course recommendations\n\n**Benefits:**\n- Centralized UI element selectors\n- Reusable methods for common interactions\n- Easy to maintain when UI changes\n- Better readability in tests\n\n#### 2. **test-scenarios.js** - Test Scenarios\nReusable scenario functions that combine page objects to test complete workflows:\n\n- `registrationScenario()` - User registration\n- `loginScenario()` - User login\n- `dashboardScenario()` - Dashboard verification\n- `createLearningGoalScenario()` - Goal creation\n- `addResourceScenario()` - Add learning resources\n- `analyticsScenario()` - Analytics verification\n- `recommendationsScenario()` - Recommendations display\n- `completeUserJourneyScenario()` - Full user flow (register → add resources → view analytics)\n- `personaActivityScenario()` - Persona-based activity simulation\n\n**Benefits:**\n- Reusable across multiple tests\n- Clear, descriptive names\n- Support for different learner personas\n- Easy to add new scenarios\n\n#### 3. **playwright-tests.js** - Test Suites\nComprehensive test suites using scenarios and page objects:\n\n- **User Registration & Authentication** - Registration and login flows\n- **Dashboard Functionality** - Dashboard features and data display\n- **Analytics & Insights** - Analytics page and charts\n- **Recommendations** - Recommendation system\n- **Persona-Based Scenarios (50 Users)** - Tests for all 6 learner personas\n- **Complete User Journeys** - End-to-end workflows\n- **Performance Tests** - Load time verification\n- **Data Validation** - Verification of 50-user test data\n\n## Test Data: 50 Learner Personas\n\nThe tests include 6 learner personas (from backend/testing/learner_personas.py):\n\n### Persona Distribution (50 users)\n1. **Consistent Learner** (30%) - 15 users\n   - Active 85% of days, high completion rate (90%)\n   - Complete 3+ resources regularly\n   - Success rate: Very high\n\n2. **Struggling Learner** (20%) - 10 users\n   - Active 50% of days, low completion rate (40%)\n   - Inconsistent engagement\n   - Success rate: Low\n\n3. **Binge Learner** (15%) - 7-8 users\n   - Active 20% of days but long sessions (4-8 hours)\n   - Completion rate: 70%\n   - Success rate: Medium-high\n\n4. **Casual Learner** (20%) - 10 users\n   - Active 35% of days, moderate sessions\n   - Completion rate: 50%\n   - Success rate: Medium\n\n5. **Perfectionist Learner** (10%) - 5 users\n   - Active 80% of days, very high completion (95%)\n   - Never misses spaced repetition\n   - Success rate: Very high\n\n6. **Procrastinator** (5%) - 2-3 users\n   - Active 10% of days, low completion (25%)\n   - High dropout rate (70%)\n   - Success rate: Low\n\n## Running the Tests\n\n### Prerequisites\n```bash\n# Install dependencies\ncd e2e-tests\nnpm install\n\n# Ensure backend is running\ncd ../backend\npython -m uvicorn main:app --reload --port 8000\n\n# Ensure frontend is running (in another terminal)\ncd ../frontend\nnpm run dev\n```\n\n### Run All Tests\n```bash\nnpm run test\n```\n\n### Run Specific Test Suite\n```bash\n# Registration & Authentication\nnpx playwright test -g \"Registration & Authentication\"\n\n# Dashboard tests\nnpx playwright test -g \"Dashboard\"\n\n# Persona tests (all 6 personas)\nnpx playwright test -g \"Persona-Based\"\n\n# Performance tests\nnpx playwright test -g \"Performance\"\n```\n\n### Run in Debug Mode\n```bash\nnpx playwright test --debug\n```\n\n### Run with UI\n```bash\nnpx playwright test --ui\n```\n\n### Generate HTML Report\n```bash\nnpx playwright test\nplaywright show-report\n```\n\n### Run Single Test File\n```bash\nnpx playwright test playwright-tests.js\n```\n\n## Test Coverage\n\n### User Flows\n- ✅ User registration\n- ✅ User login\n- ✅ Dashboard verification\n- ✅ Add learning (Chromium, Firefox, WebKit)\n- Viewport sizes\n- Timeout values\n- Screenshots/videos on failure\n- Parallel execution\n\n## Example: Adding a New Test\n\n```javascript\ntest('My new feature', async ({ page }) => {\n  const dashboard = new pageObjects.DashboardPage(page);\n  await dashboard.goto();\n  \n  // Use existing scenarios\n  const stats = await scenarios.dashboardScenario(page);\n  expect(stats.xp).toBeGreaterThanOrEqual(0);\n});\n```\n\n## Example: Using Personas in Tests\n\n```javascript\ntest('Test with specific persona', async ({ page }) => {\n  const persona = PERSONAS.perfectionist_learner;\n  const activities = await scenarios.personaActivityScenario(page, persona, 3);\n  \n  // Verify perfectionist completed activities\n  expect(activities.filter(a => a.success).length).toBe(3);\n});\n```\n\n## Troubleshooting\n\n### Tests failing with \"Timeout\"\n- Increase `TIMEOUT` in `page-objects.js`\n- Check if frontend/backend are running\n- Verify URLs in CONFIG object\n\n### Selectors not found\n- Update selectors in `page-objects.js` to match actual UI\n- Run tests with `--debug` flag to inspect elements\n- Use Inspector: `npx playwright test --debug`\n\n### Email conflicts\n- Tests use `Date.now()` for unique emails\n- Clear test data between runs if needed\n- Check database for duplicate emails\n\n## Best Practices\n\n1. **Always use Page Objects** - Don't hardcode selectors in tests\n2. **Reuse Scenarios** - Use existing scenario functions\n3. **Test One Thing** - Each test should verify one feature\n4. **Meaningful Names** - Use descriptive test names\n5. **Handle Waits** - Use `waitForURL()` for navigation\n6. **Mock Data** - Use consistent test data\n7. **Error Handling** - Check error messages in tests\n\n## Performance Benchmarks\n\nExpected performance with typical setup:\n- Dashboard: 800-1500ms\n- Analytics: 1500-2500ms\n- Recommendations: 600-1500ms\n- Full user journey: < 15 seconds\n\n## Next Steps\n\n1.
